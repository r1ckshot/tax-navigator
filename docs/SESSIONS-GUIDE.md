# SESSIONS-GUIDE — воркфлоу одного інструмента (Claude Code, VS Code)

## Що де лежить
- `research/tg-mining/` ← Telegram-майнінг і вибірки для розмітки G1. Локально, поза git (read-only до Telegram; дані і приватні цитати ніколи не публікуються).
- `docs/features/<slug>/` ← SDLC-артефакти фічі (idea-brief, CONTEXT, PRD, sad, tasks). **У git**: тут немає сирих даних людей. Писати так, ніби це читає стороння людина з тих самих чатів.
- `docs/JOURNAL.md` ← хроніка й післямортеми. Поза обов'язковим читанням — відкривається, коли треба «як ми до цього дійшли».
- Курсова доба (капстоуни, демо, повна хроніка STATE) — тег `archive/course`, у робочому дереві її немає.

## Принцип
Один інструмент, дві РОЛІ через два ТИПИ сесій. Стан живе у файлах (STATE, DECISIONS), не в чатах — тому сесії безболісно народжуються і вмирають.

## Типи сесій
**1. Сесія-ПЛАНУВАННЯ (розмова з Mike):**
- Читає: SESSIONS-GUIDE → PROJECT → STATE → релевантне з EVIDENCE, DECISIONS, `research/`.
- Видає: фази й теми в [ROADMAP.md](ROADMAP.md) і файл на кожну сесію в [sessions/](sessions/); рішення — в DECISIONS.
- Формат файла сесії: `Мета / Прочитати / Кроки / Агенти й скіли / Крок Mike / Готово коли` — пункти «Готово коли» перевіряються командою або фактом.
**2. Сесія-БІЛД (команда «Begin»):**
- Вхід: «Begin» → наступна сесія з ROADMAP за протоколом, описаним там же.
- Робить одну сесію → комітить по кроках → наприкінці ОНОВЛЮЄ STATE і стан у ROADMAP. Оновлення STATE = частина Definition of Done, без нього сесія не закрита.

## Модель за типом задачі
| Тип сесії | Модель | Чому |
|---|---|---|
| Сесія-ПЛАНУВАННЯ (архітектура, rules-matrix, SDLC-артефакти) | Opus | глибше мислення, довгі агентні сесії |
| Сесія-БІЛД (рутинний код, конфіг, тести) | Sonnet | баланс якість/ціна — дефолт (User+Local tier) |
| Звірка законодавства/rules-matrix проти офіційних джерел | Fable 5 | найвищі можливості — тут ціна помилки найвища (фінансовий продукт) |

Перемикання вручну на старті сесії: `/model opus` / `/model sonnet` / `/model fable` (або Alt+P).

## Правила контексту
- Нова задача = НОВА СЕСІЯ (не /clear — нова сесія архівує стару, `claude --resume` дає історію).
- Всередині однієї довгої задачі на ~60–70% контексту → `/compact` з фокусом на задачу ("preserve modified files list and test commands").
- Застряг двічі на тому самому → нова сесія + гостріший BRIEF.
