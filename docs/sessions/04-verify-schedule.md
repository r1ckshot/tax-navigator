# 04 · Автозвірка: розклад і що бачить Mike

Тема 1.2 · сесія 3 з 3 · гілка `feat/rules-auto-verify` · Opus · high

## Мета

Звірка запускається сама, без дедлайнів. Mike бачить лише сповіщення GitHub: бот-PR
з оновленим `verified_at`, коли все збігається, і issue з чернеткою PR, коли ні.

## Прочитати

- DECISIONS 2026-09-15 (агент і право запису ніколи в одному job; про прогін судимо за артефактом) і 2026-10-01 (бот-PR)
- `.github/workflows/tg-collector-oncall.yml` — зразок розрізу `investigate` / `open-draft`
- `.github/workflows/deploy-tg-collector.yml` — ранер `tax-navigator-vps`
- `docs/EVIDENCE.md` — коли публікуються нові ставки (мінімальна зарплата, база ZUS, обвіщення GUS)

## Кроки

1. Де запускати: тестовий `workflow_dispatch` на `ubuntu-latest` і на
   `tax-navigator-vps` — заміряти, з якого відкривається більше джерел. Можна обидва.
2. Workflow `rules-verify.yml`:
   - щомісяця повний прогін;
   - щотижня в «гарячі» вікна, коли виходять ставки нового року (вікна вивести з
     EVIDENCE, не з пам'яті);
   - щотижня легкий прогін лише `act`: змінився акт → одразу повний;
   - `workflow_dispatch`.
3. Результати:
   - **усе збігається** → job без моделі відкриває або оновлює один PR «re-verify»
     лише з `verified_at`; job перевіряє, що `params` не змінено;
   - **розбіжність або зміна акта** → issue з таблицею (значення джерела, матриці,
     посилання, дата) → `investigate` (модель, лише читання, пише `notes.md`) →
     `open-draft` (запис, без моделі) відкриває чернетку PR: правило + EVIDENCE + тест,
     а якщо змінилось число, яке бачить людина, — ще patch-версія в `package.json` і
     рядок у CHANGELOG (правило версії — CLAUDE.md §Pull requests);
   - **недоступне** → повтор до трьох днів поспіль, потім issue «перевір руками» з
     посиланням.
4. Значення 2027 або ухвалений закон (проєкт PIT UD116) → issue з міткою
   `rules-2027` — тригер теми П.1 у ROADMAP.
5. PR, відкритий `GITHUB_TOKEN`, не запускає інших workflow: тести на бот-PR самі
   не підуть. Вирішити (fine-grained PAT, GitHub App або явний `workflow_dispatch`
   тестів) і записати в DECISIONS.
6. `actionlint`; живий прогін через dispatch на гілці з навмисною розбіжністю у
   тестовому режимі.
7. `sad.md` §розклад; STATE («rules-change-monitor: 26 з 26, розклад …»); README
   («Два фонові інструменти»).
8. Тема видима ззовні лише гарантією, не екраном — версія без змін.
   `gh pr ready` → мердж.
