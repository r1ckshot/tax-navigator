## Кроки

1. `act` через ELI API Сейму: для акта з `source_url` — чи були зміни після
   `verified_at`. Зміна → стан «потребує перевірки» (число не порівнювали, тож це
   не «розбіжність»). Відповіді API — фікстурами в тести.
2. `sip.lex.pl` — комерційне джерело: замінити `source_url` на офіційне (ISAP/ELI,
   gov.pl) через `/scaffold-rule`, тобто зі звіркою значення заново, а не заміною
   рядка.
3. `edition` для `zakon.rada.gov.ua`: дата чинної редакції ПКУ на сторінці; нова
   редакція після `verified_at` → «потребує перевірки».
4. `llm` для сторінок, де число лише в тексті: модель повертає число і цитату;
   скрипт приймає результат, тільки якщо цитата дослівно є в тексті сторінки, а
   число — у цитаті. Інакше «не вдалось перевірити». Бюджет: ліміт символів на
   вхід, одна відповідь на правило.
5. Тести на кожен спосіб; мутація: підмінене число у фікстурі → «розбіжність»,
   підмінена цитата → «не вдалось перевірити».
6. Живий прогін циклу: 26 з 26 мають автоматичний стан.
