# ADR-0001 — Шари з ізольованим ядром, не Clean і не Hexagonal

- **Статус:** прийнято
- **Дата:** 2026-07-28
- **Контекст навколо:** [ARCHITECTURE.md](../../ARCHITECTURE.md), [SPEC.md](../../SPEC.md)

## Контекст

Структура вже склалась у коді (`app/lib/rules` → `calc` → адаптери →
`components`), але ніде не була описана й нічим не трималась. Питання, на яке
відповідає цей запис: **чи піднімати її до Clean або Hexagonal, чи зафіксувати
як є.**

Вхідні дані, а не смак:

- Event Storming на реальному коді дав 12 подій і 5 BC (Questionnaire, Residency,
  Calculation, Evidence, Sharing), але реальних сутностей лише 2–3 (`Answers`,
  `Rule`), а команда — одна людина.
- Інвертувати нічого: розрахунок детермінований і клієнтський, БД немає, HTTP
  немає, правила — статичний JSON у репозиторії. Порт без другої реалізації —
  це інтерфейс заради інтерфейсу.
- Ядро вже фактично чисте: нуль імпортів `react`/`next` у `app/lib/calc`,
  браузерні API зібрані в одному `storage.ts`. Тобто дисципліна є, бракує
  лише запису й перевірки.

## Рішення

Фіксуємо **шари з одностороннім правилом залежностей і детермінованим ядром**:
`presentation → adapters → calc → rules`. Ядро — без npm-залежностей.

Правило записане в `CLAUDE.md` (завантажується щосесії) і перевіряється
машинно: `npm run test:arch` (dependency-cruiser, граф імпортів) +
`app/lib/__tests__/architecture.test.ts` (браузерні глобали, яких у графі не
видно). Обидві перевірки входять у `npm test`.

**Clean відкинуто:** ізоляція, заради якої його беруть, тут уже досягнута
шарами; додаткові use-case-об'єкти й порт-інтерфейси дали б індирекцію без
другої реалізації за нею.

**Hexagonal відкинуто:** адаптер сьогодні один (веб). Порти окупаються з
другим, а не «про запас» — це той самий передчасний крок, від якого застерігає
сам матеріал модуля.

## Наслідки

**Плюси.** Ядро тестується без DOM і без моків — 86 тестів ганяються в голому
Node за ~7 с. Річна зміна податків — правка `rules.2026.json`, не логіки.
Межі не покладаються на пильність: порушення падає в `npm test`.

**Мінуси, які приймаємо усвідомлено.**

- Шар адаптерів — збірна: схема анкети, `sessionStorage`, share-лінк і
  форматування живуть поруч без спільної абстракції.
- Продуктове правило протекло в адаптер: крок квантизації виручки 2 500 zł
  і `quantizeRevenue` лежать у `share.ts`, хоча це рішення про приватність і
  пороги zdrowotnej, а не про шаринг.
- Другий інтерфейс (Telegram) не «підключиться» — його поява вимагатиме
  винесення портів, тобто саме тієї роботи, яку зараз відкладаємо.

## Коли переглядати

Тригер — поява **другого адаптера**, а не зростання кількості файлів:

1. TG-бот як другий driving-інтерфейс до того самого движка (BACKLOG, після MVP).
2. Серверна частина під платний tier (Stripe, генерація PDF) — перший driven-адаптер.
3. Агентний моніторинг змін правил (M10), якщо він писатиме в `rules.2026.json`
   автоматично, а не через ручну звірку.

Перший кандидат на винесення при будь-якому з тригерів — `calc/scenarios`:
змінюється щороку разом із податками і вже ізольований типами.
