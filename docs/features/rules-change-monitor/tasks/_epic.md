# Epic: rules-change-monitor

**Ітерація:** 1 (MVP)
**Дата створення:** 2026-08-10

## Проблема

Знання про точність `rules.2026.json` спирається на повний ручний перечит раз на рік. Дрейф (застарілий `verified_at` без підтвердження, що джерело досі актуальне) і реальні зміни правила ніяк не розрізняються між річними перечитами — Хранитель матриці не знає, чи цифра, яку він показує користувачам, досі відповідає джерелу.

## Рішення

Щомісячний автоматичний diff-звіт скриптованих джерел (`zus.pl`, `podatki.gov.pl`) проти `rules.2026.json`: кожен запис отримує один із 7 явних станів звірки, косметика відрізняється від змістовної зміни, недоступність джерела не зливається з «без змін», а раніше ветовані цифри вимагають явного підтвердження перед прийняттям.

## Scope

### Що входить

- Щомісячна автоматична звірка скриптованих джерел (`zus.pl`, `podatki.gov.pl`) проти `rules.2026.json`.
- 7 явних станів звірки на кожен запис, жоден запис не лишається без стану.
- Розрізнення косметичної відмінності від змістовної зміни (нормалізація чисел).
- Явна позначка недоступності джерела з причиною, повтор наступного циклу.
- Zахист від повернення вже ветованої/скасованої цифри — вимагає підтвердження Хранителя.
- Зведений звіт для 30-хвилинного перегляду.

### Що НЕ входить

- Персоналізовані push-сповіщення платним підписникам (v2-шар доставки) — відкладено.
- Автоматичний моніторинг `isap.sejm.gov.pl` і `tax.gov.ua` — обидва за WAF.
- Будь-яка порада, що робити зі зміною правила — фіча лише позначає стан.
- Автоматична правка `rules.2026.json` — оновлення лишається ручною дією через `/scaffold-rule`.

## Ризики

| Ризик | Severity | Mitigation |
|---|---|---|
| Хибнопозитивне спрацювання читається як персональна податкова порада | Medium | Система лише позначає зміну значення, ніколи не радить дію (product-safety.md) |
| Забагато запитів до джерела за короткий час (ризик бану/rate-limit) | Medium | Пауза між послідовними запитами до одного джерела (§4 стовп 2, S-2 крок 1) — новий патерн, не наявний прецедент |
| Challenge-сторінка WAF розпізнається як контент, записує сміттєве значення | High | Розпізнавання HTML-сигнатури challenge-сторінки → `failure_reason = 'challenge_page'`, ніколи не записується як значення (S-2 крок 4) |
| Вже ветоване значення повертається через дзеркало/кеш джерела замість первинного | High | AC-10 (S-4) — окремий стан `needs_confirmation`, що вимагає явного підтвердження Хранителя |

## Метрики успіху

1. Час перегляду готового звіту за один місячний цикл — target ≤30 хв — щомісячно.
2. Частка записів матриці в allowlist-скоупі, звірених без ручної роботи — target 100% від записів у скоупі (наразі 9/26 = 34,6% усієї матриці за дефолтним allowlist).
3. Хибнопозитивні спрацювання (косметика позначена «розбіжність») — target ≤1 на цикл.
