# 0002 — Local JSON file for cycle history and the veto list

- **Status:** Accepted
- **Date:** 2026-08-06
- **Deciders:** Mike + Claude (architecture-design, Socratic walk)

## Context

Без персистентного стану між циклами AC-09 (повторити запис, що не
вдалось перевірити) і AC-10 (позначити «потребує підтвердження», якщо
значення джерела збігається з відомою ветованою цифрою) не працюють
взагалі — обом потрібна памʼять про минулі цикли, не лише поточний.
Рішення потрібне зараз, бо звіт-генератор (§6/§10) і retry-логіка (AC-09)
читають той самий записаний стан.

## Decision drivers

- AC-09 — повторити спробу для «не вдалось перевірити», не пропустити назавжди.
- AC-10 — порівняти нове значення з відомим списком ветованих цифр.
- AC-03 — кожен запис має рівно один стан із 7 можливих, десь цей стан
  має зберігатись між циклами.
- Прецедент цієї ж сесії: `tg-assistant` ADR-0003 обрав той самий підхід
  для аналогічної задачі (соло-інструмент, один читач/писар).

## Considered options

1. **Локальний JSON-файл** — історія станів по `rule_id` + окремий
   веto-список відомих скасованих цифр (`docs/EVIDENCE.md` як джерело
   для поповнення вручну).
2. **SQLite-файл** — та сама локальність, транзакційний доступ.
3. **Без персистентного стану** — кожен цикл рахує все заново, звіряючи з
   попереднім git-комітом звіту.

## Decision outcome

**Обрано:** Опція 1. 26 записів, один читач/один писар (Хранитель матриці
через `/scaffold-rule`, не паралельний доступ) — транзакційність SQLite не
купує нічого практичного; Опція 3 виключена напряму, бо AC-09/AC-10 за
визначенням вимагають памʼять, якої немає в «рахувати заново».

## Consequences

**Positive**
- AC-09/AC-10 отримують просте джерело істини — один файл, легко
  інспектувати вручну під час дебагу.
- Узгоджено з прецедентом `tg-assistant` ADR-0003 з цієї ж сесії — той
  самий клас рішення для того самого класу задачі (соло-інструмент).

**Negative**
- Потрібен atomic-write (temp-файл + rename) — часткове аварійне
  вимкнення посеред запису ризикує лишити файл у проміжному стані.
- Веto-список поповнюється вручну (PRD §8 відкрите питання) — не
  автоматичний процес.

**Neutral**
- Формат файлу (масив записів по `rule_id` + окремий веto-масив) — деталь
  для §5 Building blocks, не цього ADR.
