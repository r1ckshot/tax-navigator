# Epic: tg-assistant

**Ітерація:** 1 (MVP)
**Дата створення:** 2026-08-10

## Проблема

Знання про попит на податковий навігатор здобувається разовими ручними заходами дослідника ринку, і кожне з них застаріває одразу після завершення. Немає відповіді на просте питання: чи люди питають про це зараз, і чи навігатор відповідає саме на те, що вони питають. Вікно вузьке — G1 не закриті, курс завершується у вересні 2026.

## Рішення

Щотижневий безнаглядний збір органічних податкових питань із чатів, де дослідник уже є учасником, з розміткою кожного як «покрито» чи «біла пляма» відносно поточної rules-матриці, без відповідей, чернеток чи відправки.

## Scope

### Що входить

- Щотижневий безнаглядний обхід чатів, де дослідник уже учасник.
- Фільтр органічних податкових питань від шуму.
- Розмітка «покрито»/«біла пляма» проти чинної rules-матриці.
- Тижневий звіт зі службовим посиланням на першоджерело.
- Надолуження пропущеного тижня + backfill історії нового чату (обмежене вікном N тижнів).

### Що НЕ входить

- Будь-яка відправка ботом (повідомлення, коментарі, реакції, вступ у групи, ЛС) — read-only місія, CLAUDE.md.
- Чернетки відповідей (окремий етап T3, BACKLOG).
- Відстеження відповідей на власні повідомлення автора.
- Чати, у яких дослідник не є учасником — без розширення членства.
- Доглиблення історії глибше вікна N тижнів або чатів, до яких дослідник приєднався до старту фічі.

| Зловживання токеном сесії акаунта | High | Облікові дані лише на машині дослідника, ніколи в git (`research/tg-mining` read-only місія) |

## Метрики успіху

1. Нові органічні питання на тиждень — target ≥2× baseline (TBD з `research/tg-mining/SUMMARY-ROUND2.md`) — щотижнево.
2. Частка тижнів зі звітом без ручного втручання — target ≥90% на ковзному 12-тижневому вікні.
3. Частка тижневих звітів, де кожне питання має дійсне службове посилання на першоджерело — target 100% з першого тижня.
