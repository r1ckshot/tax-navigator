# 0001 — Use a direct MTProto library instead of an interactive Claude+MCP session

- **Status:** Accepted
- **Date:** 2026-08-06
- **Deciders:** Mike + Claude (architecture-design, Socratic walk)

## Context

PRD US-01 вимагає, щоб тижневий цикл обходив чати **безнаглядно** — без людини
за клавіатурою. Досі весь збір робився через живу сесію Claude Code з
Telegram MCP-сервером (`research/tg-mining/01-SETUP.md`), яку Mike запускав
вручну щоразу. Це працює для разового дослідницького проходу, але не для
щотижневого автоматичного циклу — рішення потрібне зараз, бо саме воно
визначає, з чого складається §5 Container-вигляд.

## Decision drivers

- US-01 «безнаглядно обходить чати» — жодного інтерактивного кроку в
  тижневому циклі (PRD §4).
- NFR «тривалість циклу ≤30 хв без backfill» (PRD §6) — час людини на
  запуск сесії вручну в цей бюджет не вписується.
- `research/tg-mining/01-SETUP.md` вже документує сесію MTProto-акаунта,
  яку можна перевикористати без нового логіну.
- `.claude/rules/environment-limits.md` документує, що вкладений `claude -p`
  з-під іншого процесу цієї ж сесії ненадійний (дедлок на session-лоці) —
  це виключає «розкладом запускати Claude-сесію» як практичний варіант.

## Considered options

1. **Пряма MTProto-бібліотека (gramjs) у Node.js-скрипті** — читає той самий
   session-файл, запускається scheduled worker-ом без Claude в циклі.
2. **Claude Code + MCP-сервер за розкладом** — той самий MCP-сервер, що й
   зараз, але тригериться cron-ом через `claude -p`.
3. **Ручний щотижневий прогін** — статус-кво, Mike сам відкриває сесію.

## Decision outcome

**Обрано:** Опція 1. Пряма бібліотека знімає залежність від живої Claude-сесії
й ціни інтерактивного round-trip, а сесія вже є (`01-SETUP.md`) — не потрібен
повторний логін. Опція 2 виключена задокументованим дедлоком (`environment-
limits.md`); Опція 3 не автоматизує нічого, суперечить самій меті фічі.

## Consequences

**Positive**
- Цикл справді безнаглядний — жодної залежності від живої Claude-сесії.
- Перевикористовує наявний session-файл, без повторної авторизації в Telegram.

**Negative**
- Нова залежність бібліотеки-клієнта поза нульовим core продукту
  (`docs/architecture-map.md` — `calc/` без npm-залежностей; це обмеження на
  `calc/`, не на tg-assistant, але прецедент варто тримати в голові).
- Обробка помилок MTProto (включно з `FLOOD_WAIT_X`, ADR-0002) тепер лежить
  на цьому скрипті, а не делегована MCP-серверу.

**Neutral**
- LLM-класифікація «органічне питання» (якщо знадобиться, §4 майбутніх
  секцій) стає окремим API-викликом, не MCP tool-call — деталь для
  наступної стадії, не для цього ADR.
