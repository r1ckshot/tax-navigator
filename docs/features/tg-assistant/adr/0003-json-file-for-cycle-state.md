# 0003 — Local JSON file for weekly-cycle state instead of a database

- **Status:** Accepted
- **Date:** 2026-08-06
- **Deciders:** Mike + Claude (architecture-design, Socratic walk)

## Context

Цикл мусить памʼятати між тижнями: які повідомлення вже оброблені (AC-09
дедуп при catch-up), скільки тижнів історії підтягнуто для нового чату
(AC-10), і TTL 90 днів для похідних даних (PRD §6.1). Потрібне сховище, яке
переживає перезапуски скрипта — рішення потрібне зараз, бо і дедуп-логіка
(майбутнє §5), і формування звіту (майбутнє §6) читають той самий стан.

## Decision drivers

- `docs/architecture-map.md`: основний продукт цілком без БД (клієнтський
  Next.js, `SPEC.md:21-22`) — прецедент «нуль інфраструктури», якщо задача
  дозволяє.
- Соло-інструмент, один користувач, немає паралельних записувачів — знімає
  головний аргумент за транзакційність.
- PRD §6.1: похідні дані на диску мають TTL 90 днів, без сирого тексту.
- NFR duration ≤30 хв/≤2 год (PRD §6) — читання/запис стану не мають самі
  стати вузьким місцем.

## Considered options

1. **Локальний JSON-файл** — один файл зі списком оброблених питань (мітка,
   `rule_id`, timestamp, службове посилання) + маркерами catch-up на чат.
2. **SQLite-файл** — та сама локальність, але транзакційний доступ і
   SQL-запити для TTL-очистки.
3. **Postgres** — окремий сервер БД.

## Decision outcome

**Обрано:** Опція 1. Один читач/один писар, невеликий обсяг (десятки питань
на тиждень) — транзакційність SQLite не купує нічого практичного тут, а
Postgres суперечить прецеденту «нуль інфраструктури» з `architecture-map.md`
без причини, специфічної для цієї фічі.

## Consequences

**Positive**
- Нуль нової інфраструктури — узгоджено з рештою репо.
- Файл легко інспектувати вручну (`cat`/`jq`) під час дебагу тижневого циклу.

**Negative**
- Немає атомарності транзакції — часткове аварійне вимкнення посеред запису
  може лишити файл у проміжному стані; потрібен atomic-write (temp-файл +
  rename), інакше AC-09 дедуп ризикує чорнетковим станом.
- TTL-очистка (90 днів) — власноручний скрипт-фільтр, а не `DELETE ... WHERE`.

**Neutral**
- Якщо обсяг питань на тиждень колись виросте на порядок, міграція на
  SQLite лишається можливою без зміни зовнішнього контракту (той самий
  набір полів на запис).
