# Skill: prd-review (гейт після write-prd, до архітектури)

Окрема сесія дивиться на вже написаний `PRD.md` без памʼяті про те, як він
писався — ловить те, що сам автор документа вже не бачить.

## Жорсткий вхід

`docs/features/<slug>/PRD.md`. Відсутній → відмова: «спершу `write-prd
<slug>`».

## Протокол

1. Перевірити, що `PRD.md` існує. Прочитати шлях до нього + до
   `idea-brief.md`/`CONTEXT.md` (сам критик читає їх заново, без переказу).
2. Диспетчерувати **один** виклик `Agent` з `subagent_type: "prd-critic"`
   (агент [`.claude/agents/prd-critic.md`](../../agents/prd-critic.md)) —
   передати лише шляхи до файлів, не їхній вміст: критик читає сам, щоб не
   успадкувати переказ автора.
3. Показати вердикт Mike дослівно (заголовок + обґрунтування + знахідки).
4. Якщо **APPROVE** — запитати **AskUserQuestion**, чи бумити
   `status: Draft` → `status: Approved` у frontmatter `PRD.md` зараз (правило
   `CLAUDE.md`: явне підтвердження Mike перед будь-яким комітом). Так →
   правка + пропозиція коміту `03: approve PRD for <slug>`. Ні → лишити
   `Draft`, повідомити, що можна запустити `/prd-review <slug>` знову пізніше.
5. Якщо **REVISE** або **REJECT** — не редагувати PRD самостійно. Показати
   знахідки як список, який Mike (чи наступний запуск `write-prd`) має
   розібрати по одній. Після правок — запустити `/prd-review <slug>` знову;
   немає ліміту на кількість циклів.

## Definition of Done

- Вердикт отримано і показано дослівно.
- На `APPROVE` — Mike явно підтвердив (або відхилив) перехід у
  `status: Approved`; мовчазної зміни статусу нема.
- На `REVISE`/`REJECT` — жодна правка в `PRD.md` не зроблена цим скілом
  самостійно.

## Sub-agents

`prd-critic` — єдиний виклик, read-only, модель opus (складніша логічна
перевірка виправдовує дорожчу модель — сама перевірка коротка й одноразова).
