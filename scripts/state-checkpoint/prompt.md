Ти складаєш чернетку запису-чекпоінта "Закрито" для `docs/STATE.md` — логу
того, що зроблено, у форматі, який цей проєкт вже використовує. Ти не
вирішуєш, що вважати завершеним — ти лише переказуєш коміти, які вже існують.

## Порядок дій

1. **Прочитай `docs/STATE.md`.** Вивчи два-три останні блоки
   `Закрито YYYY-MM-DD (...)` під заголовком `## Зараз у роботі`, щоб
   зрозуміти формат: один рядок-заголовок з датою й короткою назвою задачі,
   далі буліти `- [x] ...`. Буліти називають ЩО зроблено, і там, де це не
   очевидно з diff'а, ЧОМУ (рішення, звірка, цифра) — ніколи не вигадуй
   "чому", якого нема в git log.
2. **Знайди межу чекпоінта сам**, не припускай її: виконай
   `git log -1 --format=%H -- docs/STATE.md`, щоб дізнатись hash останнього
   коміту, що чіпав `docs/STATE.md`. Цей коміт — межа: STATE.md уже
   відображає все аж до нього включно.
3. **Виконай `git log <той-hash>..HEAD --format="%H%n%s%n%b%n---"`**, щоб
   побачити всі коміти, яких STATE.md ще не бачив, разом з тілом коміта —
   у цьому проєкті "чому" живе саме в тілі коміта (Conventional Commits),
   не в прозі, орієнтованій на STATE.md, тож тіло часто єдине місце, де
   рішення взагалі записане.
4. **Прочитай `docs/BACKLOG.md`** — звір розділ NOW і таблицю "Курс", щоб
   заголовок чернетки використовував назву задачі, яку впізнає Майк, а не
   вигадану.
5. **Склади новий блок**:
   - Заголовок: `Закрито YYYY-MM-DD (<назва задачі>, N commits):` —
     YYYY-MM-DD це сьогоднішня дата, N — кількість комітів із кроку 3.
   - Буліти `- [x]`, по одному на змістовну зміну. Групуй fixup/typo/rebase-
     коміти в буліт тієї зміни, до якої вони належать — не роби один буліт
     на кожен коміт, якщо кілька комітів це один логічний крок.
6. **Відредагуй `docs/STATE.md`**: встав новий блок одразу під заголовком
   `## Зараз у роботі`, над існуючим найновішим блоком. Не чіпай інші
   секції файлу (`## Фаза`, `## Живі блокери`, `## Наступне`) і не видаляй,
   не переставляй, не переформатовуй наявні блоки `Закрито`.
7. **Перечитай `docs/STATE.md`**, щоб підтвердити, що редагування
   застосувалось чисто і Markdown-структура (рівень заголовка, стиль
   булітів, порожні рядки між блоками) точно збігається з сусідніми блоками.

## Обмеження

- Не комітити й не пушити. Це чернетка-пропозиція, залишена у working tree;
  людина сама перегляне `git diff` і вирішить — лишити, відредагувати, чи
  `git restore docs/STATE.md`, щоб відкинути.
- Не редагувати нічого, крім `docs/STATE.md`.
- Не вигадувати рішення, цифри чи обґрунтування, яких нема в git log. Якщо
  "чому" коміта нема ні в subject, ні в body — опиши лише "що".
- Якщо `git log <hash>..HEAD` порожній — нічого не пиши, натомість поверни
  JSON з `commits_covered: 0` і порожнім масивом `bullets`.

## Фінальний вивід

Поверни JSON-обʼєкт, що описує блок, який ти написав:

- `date`: `YYYY-MM-DD`, сьогодні.
- `heading`: точний рядок заголовка, який ти вставив (або вставив би).
- `bullets`: масив рядків-булітів, які ти написав, без початкового `- [x] `.
- `commits_covered`: ціле число — скільки комітів із кроку 3 враховано у
  булітах сумарно.

JSON має точно дзеркалити те, що реально записано у `docs/STATE.md` —
рев'юер звірить diff і вони мають збігатись.
