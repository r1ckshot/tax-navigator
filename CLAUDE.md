## Правило залежностей (карта шарів — ARCHITECTURE.md)
TypeScript таких меж не енфорсить, тож вони описані тут явно і перевіряються `npm test`.

```
presentation → adapters → calc → rules      (стрілки тільки в один бік)

app/lib/rules/       дані + типи; не імпортує нічого, крім себе
app/lib/calc/        чисті розрахунки; ЛИШЕ rules/ і себе.
                     Нуль npm-залежностей: ні react, ні next, ні будь-чого ще
app/lib/{questions,storage,share,format}   адаптери; браузерні API — тільки в storage.ts
app/components/, app/**/page.tsx, i18n/    presentation; без арифметики
```
- Жоден файл `app/lib/**` не імпортує компоненти чи сторінки.
- UI не читає `rules.2026.json` напряму — будь-яка цифра йде через `calc/`.
- Перевірка: `npm run test:arch` (граф імпортів) + `app/lib/__tests__/architecture.test.ts` (браузерні глобали, яких у графі не видно).

### Глибина артефактів = розмір фічі
Рубрика взята з курсу (`sdlc/00-overview/mvp-vs-full.md`), не вигадана. Класифікувати ДО того, як почав писати артефакти.

| Розмір | Означення | Що робимо перед кодом |
|---|---|---|
| **XS** | 1 PR, до дня, без міграцій і нового API | нічого — одразу код + тести |
| **S** | 2–5 PR, до тижня | `idea-brief` → короткий PRD → `tasks/` |
| **M+** | окремий епік, новий модуль / API / міграція | повний ланцюг: brief → PRD → `sad.md` (arc42 + ADR) → `tasks/` → test-plan |

Правило курсу дослівно: **вагаєшся між MVP і Full — бери MVP.** Дозаповнити порожні секції пізніше дешевше, ніж викинути наперед побудовані артефакти.

Потрібен наступний скіл (`write-prd`, `break-tasks`) — вендоримо один скіл у `.claude/skills/`, плагін `sdlc` цілком не ставимо (DECISIONS 2026-07-28).

## Git
- Гілка на фічу (`feat/*`, `fix/*`); у `master` напряму не пушимо і не комітимо, тільки merge після підтвердження Mike. Перевіряє `pre-commit-gate` — прозою це правило вже протікало.
- Conventional Commits: `type(scope): description`, **англійською** (subject і тіло, включно з "чому"). Один логічний крок = один коміт.
- Subject короткий (imperative); тіло коміта — тільки "чому", коли неочевидно з diff (не переказ what).
- Docs-only коміти (STATE.md/DECISIONS.md/README) — тіло практично ніколи не потрібне: сам diff вже проза.
- У тілі fix-коміта — лише root-cause/insight, без речень, що починаються з переказу "що змінилось".

**Де живе "чому" — тест на одне питання: чи переживе це рішення сам diff?**

| Відповідь | Місце | Приклад |
|---|---|---|
| Ні — пояснює саме цю зміну | тіло коміта | пастка `exclude: node_modules` у dependency-cruiser (`6d0d723`) |
| Так — обмежує майбутні рішення | `docs/DECISIONS.md` | розрахунок на клієнті; юрист — ні; критерій зупинки tg-assistant (коміта може взагалі не мати) |
| Ні те, ні те — як ми до цього дійшли | `docs/JOURNAL.md` | заміри 9p, хибний діагноз seccomp, відкинутий переїзд на WSL2 |

**Ніколи в двох місцях одночасно.** Історія про depcruise-привида свого часу лежала в коміті, STATE.md і capstone-нотатці — три копії неминуче розходяться.
- Нові коміти замість `--amend`; без `--no-verify`; без force-push до `master`.
- Стейджити файли за іменем, не `git add -A` наосліп — перевіряти `git status` перед комітом.
- `.env` ніколи в git, тільки `.env.example`. Стейджинг секрету ловлять два різні шари: агентський (`pre-commit-gate`, дивиться на команду) і git-рівневий (`.githooks/pre-commit`, дивиться на індекс). Другий покриває те, чого перший не бачить — команду, набрану людиною в терміналі; вмикається один раз на клон: `git config core.hooksPath .githooks`.
- **Перед кожним комітом — явне підтвердження Mike.** Показати diff/список файлів, дочекатись "так", тільки тоді комітити.
- Атрибуція Claude в комітах/PR **увімкнена за замовчуванням** і сама підставляє поточну модель — ключ `attribution` у `settings.json` не потрібен, а вписаний туди рядок став би статичним і брехав би при `/model`. Ключ жив у репо 2026-08-04 → 08-05 зі значенням `true` замість рядка і весь цей час глушив увесь `settings.json` (схема чекає текст трейлера); прибраний. Коміти до 2026-08-04 трейлера не мають, і заднім числом його не дописуємо — крім п'яти комітів того ж дня, переписаних одразу.
- **Гарантує трейлер не конфіг, а хук:** `attribution` лише кладе інструкцію в контекст, і її можна проґавити (2026-08-05 так пішли два коміти). Механічна перевірка — четвертий чек у `pre-commit-gate` (репо) і `~/.claude/hooks/require-attribution.mjs` (усі проєкти). Обидва дивляться на сам факт трейлера, не на імʼя моделі.
- **PR відкривається рано і чернеткою.** Гілка йде в `origin` після першого ж атомарного коміта, `gh pr create --draft` — одразу за ним, не наприкінці роботи. Чернетка не просить рев'ю, вона показує напрямок: хибний напрямок видно за один коміт, а не за десять. Готовність оголошує `gh pr ready` — лише тоді PR просить очей.
- Решта PR-флоу (title-конвенція, тіло, темплейт, `Closes #N`, авто-рев'ю) — секція `## Pull requests`, додається уроком 9.4 разом із текою `.github/`.

## Definition of Done
"Готово коли" з STATE.md виконано → тести проходять → коміти атомарні → STATE.md оновлено → рішення (якщо є) записане в DECISIONS.md → **останній крок: перечитати STATE.md і BACKLOG.md очима наступної сесії.**

Останній крок не формальність. У STATE не має лишитись незакритих `[ ]` від щойно зробленого, а в BACKLOG — виконаних рядків у NOW; наступна задача названа в обох. 2026-07-29 роботу тричі оголошено завершеною при застарілому NOW і чеклісті з невідміченими пунктами — це той самий пропуск, що й зелений гейт без предмета перевірки: результат проголошено, а не звірено.
