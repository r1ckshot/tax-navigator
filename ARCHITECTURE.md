# ARCHITECTURE

Патерн: **шарова архітектура з ізольованим детермінованим ядром** (rules-as-data),
feature-first усередині шарів. Обґрунтування вибору й тригери перегляду —
[docs/adr/0001-layered-with-isolated-core.md](docs/adr/0001-layered-with-isolated-core.md).

> **Що тут свідомо НЕ пишеться:** інвентар модулів, конвенції з `file:line`,
> UI-фундамент і C4 — вони живуть у [docs/architecture-map.md](docs/architecture-map.md), який генерує скіл
> `map-architecture` і читають наступні стадії SDLC. Цей файл — для людини: шари,
> правило залежностей, куди класти новий код. Карта звіряється з ним і не
> перезаписує його; знайдені розходження перелічені в її секції «Звірка».

## Шари

| Шар | Де | Що там живе | Кому дозволено імпортувати |
|---|---|---|---|
| **rules** | `app/lib/rules/` | `rules.2026.json` (кожне правило = params + `source_url` + `verified_at`) і типи доступу до нього | нічого, крім себе |
| **calc** | `app/lib/calc/` | резидентство, ZUS, 4 сценарії, діапазони — чисті функції | `rules/` |
| **adapters** | `app/lib/questions/`, `storage.ts`, `share.ts`, `format.ts` | схема анкети, чернетка в `sessionStorage`, share-лінк, форматування | `calc/`, `rules/`, одне одного |
| **presentation** | `app/components/`, `app/**/page.tsx`, `app/layout.tsx`, `app/lib/i18n/` | React, CSS Modules, українські тексти | усе нижче |

## Правило залежностей

```
presentation → adapters → calc → rules
```

Стрілки йдуть тільки в один бік. Конкретно:

- `rules/` — найнижчий шар: дані + типи, нуль імпортів назовні.
- `calc/` — **нуль зовнішніх залежностей**: ні `react`, ні `next`, ні будь-якого
  іншого npm-пакета. Розрахунок мусить рахуватись у голому Node.
- `calc/` не знає про адаптери: ні про чернетку, ні про лінк, ні про схему анкети.
- Жоден файл `app/lib/**` не імпортує компоненти чи сторінки.
- Браузерні API (`window`, `document`, `sessionStorage`) — лише в `storage.ts`.
- UI не читає `rules.2026.json` напряму: будь-яка цифра доходить до екрана
  через `calc/`, інакше вона обходить розрахунок і його тести
  (див. [.claude/rules/evidence-numbers.md](.claude/rules/evidence-numbers.md)).

## Куди класти новий код

| Що додаєш | Куди | Ознака правильного місця |
|---|---|---|
| Ставку, поріг, ліміт | `rules/rules.2026.json` | має `source_url` + `verified_at` |
| Нову форму оподаткування | `calc/scenarios/` | тестується без DOM, повертає `Range` |
| Нове питання анкети | `questions/schema.ts` | впливає на висновок, інакше питати не треба |
| Новий екран / вигляд | `components/` | не містить арифметики, лише показує |
| Текст користувачу | `i18n/uk.ts` | у компонентах немає рядків-літералів |

## Чим це тримається

Без машинної перевірки правило залежностей — побажання: TypeScript таких меж не
енфорсить, а наступна сесія (людська чи агентна) зріже кут непомітно.

```
npm run test:arch   # dependency-cruiser: граф імпортів (.dependency-cruiser.cjs)
npm test            # vitest (71) + арх-тести + test:arch
```

Дві перевірки, бо вони бачать різне: граф ловить імпорти, але не бачить
браузерні глобали — `window.sessionStorage` не є імпортом. Глобали ловить
`app/lib/__tests__/architecture.test.ts` скануванням тексту.

Кожне правило перевірене навмисною поломкою (імпорт `react` у `calc/`, цикл,
читання JSON з компонента) — усі падають, коли межу порушено. Це не формальність:
`core-no-external` спершу був привидом через `exclude: node_modules`, який
викидав npm-ребра з графа, і зелений статус нічого не означав.

## Відомі зміщення (свідомі, не борг наосліп)

- `app/lib/i18n/uk.ts` лежить у `lib/`, але за роллю це presentation. Ядром не
  імпортується, тож правило не порушує; перенесення — косметика, не зараз.
- `REVENUE_MIN/MAX/STEP` і `quantizeRevenue` живуть у `share.ts`, хоча крок
  2 500 zł — продуктове рішення (приватність + збіг із порогами zdrowotnej),
  а не деталь шарингу. `questions/schema.ts` і `storage.ts` імпортують їх звідти.
  Кандидат на переїзд у `calc/`, коли квантизація знадобиться ще десь.
